# StudyFlow

学习任务、时间规划、专注计时，支持注册登录与管理员用户管理。

## 启动

已构建的 Windows 程序可直接运行：

```powershell
.\studyflow.exe
```

打开 <http://127.0.0.1:8080>。网页由 Go 程序提供，不能再通过双击 `index.html` 使用。

从源码启动需要 Go 1.26 或以上版本，无需 Node、C 编译器或独立数据库服务：

```powershell
go run .
```

重新构建单文件程序（网页资源会嵌入程序）：

```powershell
go build -trimpath -o studyflow.exe .
```

## 账号与数据

- 首次启动自动创建管理员：`admin / 110623`。后续启动保留管理员修改后的密码。
- 登录页支持普通账号注册；用户名不区分英文字母大小写，可使用文字、数字、下划线、短横线，1–32 个字符且不超过 72 个 UTF-8 字节。注册密码为 6–72 个 UTF-8 字节。
- 每个账号独立保存任务、子任务、日程、专注记录与计时设置，新账号从空数据开始。
- 管理员登录后点击「用户管理」，可查看所有账号、注册时间、最近登录时间与有效登录会话数量。
- 重置普通用户密码后，新密码就是该账号保存的用户名（包括原有大小写），所有旧登录会话立即失效。允许使用这一较短的重置密码登录，再通过「修改密码」设置新密码。
- 删除普通用户会一并删除其学习数据和登录会话。管理员不能被删除或通过用户管理重置密码，可使用「修改密码」。
- 修改自己的密码会让所有设备退出登录。登录会话有效期为 7 天。
- 原版 `localStorage` 数据不会自动归属任何账号。登录尚无后台数据的账号后，可点击「导入浏览器旧数据」明确导入；浏览器旧数据会保留。
- 页面显示保存状态；网络失败保留本页修改，支持重试与 JSON 导出备份。关闭仍有未保存修改的页面时会提示。
- 多窗口或多设备保存采用版本检查，遇到冲突停止保存。导出本页备份后刷新取得最新版本，再手动处理差异；当前没有自动合并或 JSON 备份导入功能。

## 后端设计

一个 Go 进程负责静态网页、JSON API 与登录认证。数据库使用纯 Go SQLite 驱动，默认文件为当前工作目录下的 `data/studyflow.db`。

SQLite 使用 **WAL（预写日志）模式**、8 个数据库连接和 5 秒写锁等待时间：多个请求可以同时读取，读取通常不阻塞写入，但同一时刻仍只有一个写入者。用户学习数据作为 JSON 文档按账号存储，版本号在数据库中原子递增。适用于单机部署、读多写少的学习应用。

WAL 是磁盘数据库的并发模式，不是内存数据库。Redis 是另一种服务；当前项目引入它只会增加部署和持久化管理成本。数据库应放在本机磁盘，不要将 WAL 数据库放在网络共享盘上，也不要跨机器共享此文件部署。

密码使用 bcrypt 哈希；浏览器只保存 HttpOnly、SameSite=Strict 的随机登录 Cookie，数据库只存会话令牌的哈希。API 检查登录、角色与跨站请求，学习数据接口始终按当前登录账号确定归属。登录与注册按直接连接 IP 限流，每 10 分钟合计最多 40 次；服务不信任客户端提交的代理 IP 头。

## 配置与部署

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `STUDYFLOW_ADDR` | `127.0.0.1:8080` | 监听地址；局域网使用可设为 `0.0.0.0:8080` |
| `STUDYFLOW_DB` | `data/studyflow.db` | 建议部署时使用固定绝对路径，避免切换工作目录后创建另一份数据库 |
| `STUDYFLOW_SECURE_COOKIE` | 未启用 | HTTPS 部署时设置为 `1`，登录 Cookie 仅经 HTTPS 发送 |

例如在局域网提供服务：

```powershell
$env:STUDYFLOW_ADDR = '0.0.0.0:8080'
$env:STUDYFLOW_DB = 'D:\StudyFlowData\studyflow.db'
.\studyflow.exe
```

公网部署通过反向代理提供 HTTPS，保留原始 Host、使用同源网页与 API，并启用 Secure Cookie。首次部署后通过「修改密码」更换初始管理员密码。反向代理后的登录限流按代理连接 IP 计算，如需较多用户同时登录，应在代理层配置客户端限流并调整后端策略。

## 备份

最简单的完整备份方式：停止程序后，复制整个数据库目录（包含可能存在的 `.db-wal`、`.db-shm` 文件）。恢复时也先停止程序，再恢复整个目录。运行中不要只复制 `.db` 文件，否则可能遗漏 WAL 中已提交的数据。备份包含全部账号数据、密码哈希和会话，应妥善保管。
